# My-Expense-app (家計簿 Web アプリ)

スプレッドシートの代わりに、スマホとPCでデータを同期しながら使える家計簿 Web アプリです。
ビルド不要・フレームワーク不要の Vanilla JS + Firebase (Firestore) 構成です。

## 機能

- **収入・支出・貯蓄の記録** — 日付・種別(収入/支出/貯蓄)・カテゴリ・金額・メモを入力
- **貯蓄・投資の記録** — 株式や投資信託の購入などは「貯蓄」として記録でき、支出・収支・累計貯金額には影響しない(現金が資産に形を変えただけとして中立に扱う)。Need/Want/SaveグラフのSave実績にも自然に反映される
- **月別表示** — 月ごとの記録を切り替えて閲覧(◀ / ▶ で移動、「今月」ボタンで戻る)
- **年間表示** — 「月別」「年間」タブで切り替え、収支・予算・Need/Want/Save・記録一覧を年単位で確認可能(予算目標は月間予算×12で計算)
- **月別の収支推移グラフ** — 年間表示のときだけ、その年の1月〜12月の収入・支出を棒グラフで表示し、月ごとの増減が一目でわかる(バーにカーソルを合わせると金額を表示。縦軸にはキリの良い間隔で金額目盛りを表示)
- **サイドバーナビゲーション(PC)** — 画面幅が広いPCではダークカラーのサイドバーを表示し、「概要」「予算」「予定と実績」「Need/Want/Save」「記録一覧」の各セクションへワンクリックで移動可能。現在スクロールして見ているセクションのリンクが自動でハイライトされる。スマホなど画面が狭い場合はサイドバーを自動的に非表示にし、従来通り上部ヘッダーのみのレイアウトになる
- **月間サマリー** — 収入合計・支出合計・収支を自動集計
- **累計貯金額** — 月をまたいだ全期間の収支合計を常に表示。今月の貯蓄額と、それが累計に対して何%の増減率かも合わせて表示
- **予算管理** — カテゴリごとに月間予算を設定し、実際の支出と比較。全体は進捗バーで、カテゴリごとの内訳は使用率(%)で表示(80%超は黄色、100%超(予算オーバー)は赤色で警告)
- **予定と実績** — 支出は予算、収入は「収入目標」(給与・副収入・その他収入を月額で設定)を基準に、予定額と実績額を横棒グラフで比較表示。目標未設定のときは案内メッセージを表示
- **賞与(ボーナス)の設定** — 収入目標編集画面で、賞与が出る月(複数選択可)と「給与の何か月分か」を設定すると、その月だけ収入の予定額に自動で上乗せされる(年間表示ではボーナス月数分をまとめて加算)
- **Need / Want / Save (50:30:20)** — 今月の収入を基準に、必要な支出・欲しい物の支出・貯蓄の割合をドーナツグラフで表示。各カテゴリの使用状況を目標に対する進捗として可視化
- **編集・削除** — 記録した内容はあとから修正・削除可能
- **並び替え** — 「今月の記録」の日付・種別・カテゴリ・金額の見出しをクリックして並び替え(再クリックで昇順/降順切り替え)
- **絞り込み** — 「今月の記録」を種別(支出/収入/貯蓄)・カテゴリで絞り込み表示。種別を変えるとカテゴリの選択肢もその種別のものだけに絞られる
- **給与明細の内訳入力** — 収入・カテゴリ「給与」を選ぶと「給与明細の内訳を入力する」ボタンが出現。総支給額・交通費・所得税・住民税・社会保険料を入力すると手取り額(差引支給額)を自動計算し、記録される金額に反映(税金や社会保険料は実際には手元に入らないお金なので、家計簿上の収入・収支には手取り額だけが影響する)。内訳を入力した記録は一覧に「内訳」ボタンが表示され、いつでも総支給額や天引き額を見返せる
- **メール/パスワードでログイン** — 同じアカウントでログインすればスマホ・PC間でリアルタイムに同期
- **CSV エクスポート** — 全記録を CSV でダウンロード(Excel 対応の BOM 付き UTF-8)
- **CSV インポート** — 既存のスプレッドシートから CSV 経由でデータ移行
- **メールからの読み込み** — Vpass (三井住友カード) の利用通知メールをGmailから検索し、利用明細を記録として取り込み

## セットアップ

このアプリはデータの保存・同期に [Firebase](https://firebase.google.com/) (無料枠) を使います。
自分専用の Firebase プロジェクトを作成し、設定値をアプリに渡すだけで動きます。

### 1. Firebaseプロジェクトを作成

1. [Firebase コンソール](https://console.firebase.google.com/) にアクセスし、新規プロジェクトを作成
2. 左メニュー「Authentication」→「Sign-in method」タブ →「メール/パスワード」を有効化
3. 左メニュー「Firestore Database」→「データベースの作成」→ 本番モードを選択(リージョンは `asia-northeast1` など任意)
4. Firestore の「ルール」タブを開き、このリポジトリの `firestore.rules` の内容を貼り付けて「公開」
   - このルールにより、`firestore.rules` 内で指定したメールアドレス以外は一切データを読み書きできません
   - 公開アプリにしても、他人が新規登録しても、そのメールアドレス以外は使えないようになっています
   - 別のメールアドレス(家族など)にも使わせたい場合は、`firestore.rules` の `request.auth.token.email == "..."` の条件を
     `request.auth.token.email in ["...", "..."]` のように書き換えてください
5. 左メニュー「プロジェクトの設定」(歯車アイコン) →「全般」→「マイアプリ」→ ウェブアプリを追加 (`</>` アイコン)
6. 表示された `firebaseConfig` の値をコピー

### 2. 設定ファイルを作成

```bash
cp js/firebase-config.example.js js/firebase-config.js
```

`js/firebase-config.js` を開き、`YOUR_API_KEY` などのプレースホルダーを手順1でコピーした値に置き換えます。

このファイルは `.gitignore` に含まれているため、そのままでは Git にコミットされません。
GitHub Pages などで公開する場合は、後述の「公開方法」を参照してください
(Firebase の Web 設定値は非公開情報ではなく、コミットしても問題ありません)。

### 3. ローカルで起動

ブラウザの ES Modules 制限により、`index.html` を直接ダブルクリックして開く(`file://`)のでは動作しません。
簡易 HTTP サーバー経由で開いてください。

```bash
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

初回はログイン画面で「新規登録」タブからメールアドレスとパスワードを登録してください。

## スマホと PC でデータを共有する

同じ Firebase アカウント(同じメールアドレス)でログインすれば、スマホと PC で自動的にデータが同期されます。
ローカルの `python3 -m http.server` はそのマシン上でしかアクセスできないため、実際にスマホからも使うには、
以下のいずれかの方法でアプリをインターネット上に公開する必要があります。

### 公開方法 (GitHub Pages の例)

1. `js/firebase-config.js` を `.gitignore` から外すか、`git add -f js/firebase-config.js` でコミットに含める
2. このブランチを `main` にマージ (または Pages の対象ブランチに指定)
3. リポジトリの Settings → Pages → Source で対象ブランチ・ルートディレクトリを選択
4. 発行された `https://<ユーザー名>.github.io/My-Expense-app/` にスマホ・PC両方からアクセス
5. Firebase コンソールの「Authentication」→「Settings」→「承認済みドメイン」に、その GitHub Pages のドメインを追加

Netlify や Vercel など、他の静的ホスティングサービスでも同様に公開できます。

## スプレッドシートからの移行 (CSV インポート)

今使っているスプレッドシートを以下の列構成の CSV にして保存し、「CSVインポート」ボタンから取り込めます:

| 日付 | 種別 | カテゴリ | 金額 | メモ |
|------|------|----------|------|------|
| 2026-07-20 | 支出 | 食費 | 1500 | スーパー |
| 2026/7/25 | 収入 | 給与 | 300000 | |

- **日付**: `2026-07-20` / `2026/7/20` / `2026年7月20日` / `26/7/20` (2桁年) のいずれの形式でも可
- **種別**: 「収入」または「支出」(`income` / `expense` も可)
- **金額**: 数値(カンマ・¥ 記号入りでも可)
- 1行目がヘッダー行の場合は自動的にスキップされます
- 形式を認識できない行はスキップされ、件数が表示されます

「概要」テンプレート系スプレッドシートの [取引] タブ(支出の表: 日付/金額/説明/カテゴリ、
収入の表: 同じ並びで右側に配置)をそのままCSVエクスポートした形式も自動判定して取り込めます。
カテゴリ名がアプリのカテゴリと完全一致しない場合(例: 「交通費」→「交通」、「水道光熱費」→「水道・光熱」)
は自動的に読み替え、対応表にないカテゴリは「その他支出」「その他収入」として取り込まれます。

### クレジットカードの利用履歴CSV

Vpassなど、カード会社サイトからダウンロードした利用履歴CSV(1行目が
「氏名,カード番号(マスク済み),カードブランド」、以降の行が「利用日,利用先,
利用金額,支払回数,今回回数,今回支払金額,備考」の形式)もそのまま取り込めます。
このCSVは Shift_JIS で保存されていることが多いため、文字化けする場合は自動的に
Shift_JIS として読み直します。全件「支出」として取り込まれ、カテゴリは利用先の
店名から自動推測されます(Suica/PASMOなどの交通系、コンビニ・飲食店などの食費系、
Google Play・Steam・Amazonなどの趣味・娯楽系を判定。判定できないものは「その他支出」)。
末尾の合計行は自動的にスキップされます。

## 給与明細の内訳(総支給額・税金・交通費)について

会社からの給与は、額面(総支給額)と実際に振り込まれる金額(手取り)が
所得税・住民税・社会保険料の天引きにより異なります。これを記録するには:

1. 種別「収入」・カテゴリ「給与」を選ぶ
2. 「給与明細の内訳を入力する」ボタンを押す
3. 総支給額・交通費(内訳確認用)・所得税・住民税・社会保険料を入力すると、
   手取り額(差引支給額)が自動計算され、上の「金額」欄に反映されます

家計簿は実際にお金が動いた額を記録するものなので、税金や社会保険料は
そもそも手元に届かないお金として扱い、**収入・収支・累計貯金額には手取り額のみ**が
影響します。入力した内訳は記録一覧の「内訳」ボタンからいつでも見返せます
(総支給額のうちいくらが税金・社会保険料・交通費だったかを確認できます)。
交通費のみを別枠で管理したい場合は、収入カテゴリを追加する形でも対応できます。

## Need / Want / Save (50:30:20) について

家計の定番ルール「50:30:20」に基づき、今月の収入を基準として以下のように分類します:

- **Need (必要, 目標50%)**: 食費・住居・水道光熱・通信・交通・医療・教育・日用品
- **Want (欲しい物, 目標30%)**: 交際費・趣味娯楽・衣服美容・その他支出
- **Save (貯蓄, 目標20%)**: 収入 − Need − Want (実際に手元に残った金額)

上記に無い支出カテゴリは自動的にWant扱いになります。カテゴリ分類を変更したい場合は
`js/app.js` の `NEED_CATEGORIES` / `WANT_CATEGORIES` を編集してください。

「今月の予算」の各カテゴリ名の左には、Need(青)/Want(黄)を示す
色ドットが付き、グラフの凡例にも該当カテゴリの一覧が表示されるため、どのカテゴリが
どちらに分類されているか一目で分かります。

## メールからの読み込み機能のセットアップ

「メールから読み込み」ボタンは、Gmail内の Vpass (三井住友カード) の「ご利用のお知らせ」メールを検索し、
利用明細を自動で記録として取り込みます。お店の名前から Suica/PASMO 等の交通系は「交通」、
コンビニ・飲食店は「食費」など、よくあるパターンをある程度自動でカテゴリ分けしますが、
判定できないものは「その他支出」になるため、あとで見直してください。一度取り込んだメールは記録され、
重複して取り込まれることはありません。

使うには、Google Cloud 側でOAuth認証の設定が別途必要です(Firebaseと同じGoogle Cloudプロジェクトを流用できます)。

1. [Google Cloud Console](https://console.cloud.google.com/) で、Firebaseプロジェクトと同じプロジェクトを選択
2. 「APIとサービス」→「ライブラリ」で **Gmail API** を検索して有効化
3. 「APIとサービス」→「OAuth同意画面」を設定
   - User Type は「External」を選択
   - スコープに `https://www.googleapis.com/auth/gmail.readonly` を追加
   - 「テストユーザー」に自分のGmailアドレスを追加(この状態なら審査不要ですぐ使えます)
4. 「認証情報」→「認証情報を作成」→「OAuthクライアントID」
   - アプリケーションの種類: 「ウェブアプリケーション」
   - 「承認済みのJavaScript生成元」に、公開先のURL (`https://<ユーザー名>.github.io` など) と、
     ローカルで試す場合は `http://localhost:8000` を追加
5. 作成されたクライアントIDをコピー

```bash
cp js/google-config.example.js js/google-config.js
```

`js/google-config.js` を開き、`YOUR_CLIENT_ID...` の部分をコピーしたクライアントIDに置き換えます。
このファイルも `.gitignore` 対象です。GitHub Pagesなどで公開する場合は `firebase-config.js` と同様、
`git add -f js/google-config.js` でコミットに含めてください(OAuthクライアントIDも非公開情報ではありません)。

## データの保存について

記録は Firestore に保存され、ブラウザにはオフラインキャッシュ(IndexedDB)が作られます。
オフラインでも記録の閲覧・追加は可能で、オンラインに戻ると自動的に同期されます。

## 構成

```
index.html                       … 画面 (UI)
css/style.css                    … スタイル
js/app.js                        … ロジック (認証・Firestore同期・集計・CSV入出力)
js/firebase-config.example.js    … Firebase設定のテンプレート
js/firebase-config.js            … 自分のFirebase設定 (.gitignore対象、要作成)
js/google-config.example.js      … Google OAuth設定のテンプレート (メール読み込み用)
js/google-config.js              … 自分のGoogle OAuth設定 (.gitignore対象、任意)
firestore.rules                  … Firestoreセキュリティルール
```

フレームワークやビルドツールは使用していません (Vanilla JS)。
