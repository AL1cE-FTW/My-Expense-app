# My-Expense-app (家計簿 Web アプリ)

スプレッドシートの代わりに、スマホとPCでデータを同期しながら使える家計簿 Web アプリです。
ビルド不要・フレームワーク不要の Vanilla JS + Firebase (Firestore) 構成です。

## 機能

- **収入・支出・貯蓄の記録** — 日付・種別(収入/支出/貯蓄)・カテゴリ・金額・メモを入力
- **貯蓄・投資の記録** — 株式や投資信託の購入などは「貯蓄」として記録でき、支出・収支・累計貯金額には影響しない(現金が資産に形を変えただけとして中立に扱う)。Need/Want/SaveグラフのSave実績にも自然に反映される
- **月別表示** — 月ごとの記録を切り替えて閲覧(◀ / ▶ で移動、「今月」ボタンで戻る)
- **年間表示** — 「月別」「年間」タブで切り替え、収支・予算・Need/Want/Save・記録一覧を年単位で確認可能。今年を表示している間、目標は**経過した月数で按分**される(8月なら月間予算×8)。年初来3か月の実績を12か月分の目標と比べても意味がないため。過去の年・未来の年は12か月分
- **月別の収支推移グラフ** — 年間表示のときだけ、その年の1月〜12月の収入・支出を棒グラフで表示し、月ごとの増減が一目でわかる(バーにカーソルを合わせると金額を表示。縦軸にはキリの良い間隔で金額目盛りを表示)
- **サイドバーナビゲーション(PC)** — 画面幅が広いPCではダークカラーのサイドバーを表示し、「概要」「予算」「予定と実績」「立替金」「Need/Want/Save」「記録一覧」の各セクションへワンクリックで移動可能。現在スクロールして見ているセクションのリンクが自動でハイライトされる。スマホなど画面が狭い場合はサイドバーを自動的に非表示にし、従来通り上部ヘッダーのみのレイアウトになる
- **月間サマリー** — 収入合計・支出合計・収支を自動集計
- **累計貯金額** — 月をまたいだ全期間の収支合計を常に表示。今月の貯蓄額と、それが先月末時点の累計に対して何%の増減かも合わせて表示
- **予算管理** — カテゴリごとに月間予算を設定し、実際の支出と比較。全体は進捗バーで、カテゴリごとの内訳は使用率(%)で表示(80%超は黄色、100%超(予算オーバー)は赤色で警告)。進捗バーは**予算を設定したカテゴリの支出だけ**を分子にする(分母と対象を揃えるため)。予算を設定していないカテゴリの支出は、バーの下に「予算外: ¥◯◯」として別に表示される
- **予定と実績** — 支出は予算、収入は「収入目標」(給与・副収入・その他収入を月額で設定)を基準に、予定額と実績額を横棒グラフで比較表示。目標未設定のときは案内メッセージを表示
- **賞与(ボーナス)の設定** — 収入目標編集画面で、賞与が出る月(複数選択可)と「給与の何か月分か」を設定すると、その月だけ収入の予定額に自動で上乗せされる(年間表示では、今年のうち**到来済みのボーナス月の分だけ**加算する。未到来の賞与まで目標に足すと達成率が実態より低く見えるため)
- **Need / Want / Save (50:30:20)** — 今月の収入を基準に、必要な支出・欲しい物の支出・貯蓄の割合をドーナツグラフで表示。各カテゴリの使用状況を目標に対する進捗として可視化。**給与を登録する前でも、収入目標を設定していればそれを基準に表示される**(給与は月末にまとめて記録することが多く、実績だけを基準にすると、使いすぎに気づきたい月の前半こそ何も出ないため)。実績が目標を超えたら自動で実績に切り替わり、どちらを基準にしているかはグラフの下に表示される
- **立替金(仮払い)の管理** — 出張費など「自分が先に払って後で会社から返金される」支出に立替チェックを付けると、専用セクションに未回収合計と一覧が表示される。「精算」ボタンから返金日を入れるだけで、同額の収入(カテゴリ「立替金返金」)が自動作成されて相殺される。この返金は「稼いだお金」ではないので、**収入目標の実績と Need/Want/Save の収入には数えない**(サマリーの「収入」には相殺のため含まれる)
- **登録日の記録** — 取引日とは別に「いつ記入・インポートしたか」を各記録に保存し、記録一覧の「登録日」列に表示(クリックで並び替えも可能)
- **編集・削除** — 記録した内容はあとから修正・削除可能。「編集」を押すと**その場でポップアップが開く**ので、記録一覧(ページ最下部)と入力フォーム(ページ上部)のあいだをスクロールで往復せずに直せる
- **並び替え** — 「今月の記録」の日付・種別・カテゴリ・金額・登録日の見出しをクリック(またはキーボードで選んで Enter / Space)して並び替え(再操作で昇順/降順切り替え)
- **絞り込み** — 「今月の記録」を種別(支出/収入/貯蓄)・カテゴリ・日付で絞り込み表示。種別を変えるとカテゴリの選択肢もその種別のものだけに絞られる。日付を選ぶとその日の記録だけが表示され(見出しもその日付になる)、別の月の日を選んだ場合は自動でその月へ移動する
- **給与明細・賞与明細の内訳入力** — 収入・カテゴリ「給与」または「賞与」を選ぶと内訳入力欄が出現(カテゴリに応じて項目が切り替わる)。「給与」は支給(本給・勤務地手当・通勤手当・時間外勤務手当・給与調整)と控除(寮社宅費・健康保険・介護保険・厚生年金・雇用保険料・所得税・住民税・その他控除)、「賞与」は支給(賞与額)と控除(健康保険・介護保険・子ども支援金・厚生年金・雇用保険料・所得税)を入力すると手取り額(差引支給額)を自動計算し、記録される金額に反映(税金や社会保険料は実際には手元に入らないお金なので、家計簿上の収入・収支には手取り額だけが影響する)。内訳を入力した記録は一覧の「内訳」ボタンからポップアップでいつでも見返せる
- **家賃の給与天引きに対応** — 控除の「寮社宅費」に入れると、同額の「支出・住居」が自動で記録される。家賃は税金と違って生活に使ったお金なので、住居の予算にも Need/Want/Save にもきちんと乗り、天引きになる前の月と数字が地続きになる
- **メール/パスワードでログイン** — 同じアカウントでログインすればスマホ・PC間でリアルタイムに同期
- **パスワードの再設定** — ログイン画面の「パスワードをお忘れですか?」から、登録したメールアドレス宛に再設定メールを送信
- **読み込み失敗時の案内** — Firebase の SDK 自体が読み込めなかった場合(通信不調・広告ブロッカーなど)は、白い画面ではなく原因と対処を示す画面を表示
- **CSV エクスポート** — 全記録を CSV でダウンロード(Excel 対応の BOM 付き UTF-8)
- **分析用に書き出す** — 記録に加えて予算・収入目標・立替の紐づけ・給与明細の内訳までを1つの JSON にまとめて書き出す。Claude などの AI に読ませて分析してもらう用。集計ルール(貯蓄は中立・返金は収入に数えない・年間は経過月数で按分など)の説明も同梱するので、画面と食い違う数字で分析されない
- **CSV インポート** — 既存のスプレッドシートから CSV 経由でデータ移行
- **帳簿 (簿記の見方)** — 単式で入力した記録から仕訳・合計試算表・損益計算書・貸借対照表を自動で組み立て。期首残高を1回入れるだけで、現預金・投資資産・カード未払金・純資産が見える
- **メールからの読み込み** — Vpass (三井住友カード) の利用通知メールをGmailから検索し、利用明細を記録として取り込み
- **未確定(仮)と確定の管理** — メールから取り込んだ速報は「仮」として表示し、あとでカード利用履歴CSV(確定明細)を取り込むと自動で突き合わせて確定版に置き換え(二重登録を防止)

## セットアップ

このアプリはデータの保存・同期に [Firebase](https://firebase.google.com/) (無料枠) を使います。
自分専用の Firebase プロジェクトを作成し、設定値をアプリに渡すだけで動きます。

### 1. Firebaseプロジェクトを作成

1. [Firebase コンソール](https://console.firebase.google.com/) にアクセスし、新規プロジェクトを作成
2. 左メニュー「Authentication」→「Sign-in method」タブ →「メール/パスワード」を有効化
3. 左メニュー「Firestore Database」→「データベースの作成」→ 本番モードを選択(リージョンは `asia-northeast1` など任意)
4. Firestore の「ルール」タブを開き、このリポジトリの `firestore.rules` の内容を貼り付けて「公開」
   - このルールにより、`firestore.rules` 内で指定したメールアドレス以外は一切データを読み書きできません
   - 公開アプリにしても、他人が新規登録しても、そのメールアドレス以外は使えないようになっています
   - 別のメールアドレス(家族など)にも使わせたい場合は、`firestore.rules` の `allowedEmails()` が返す配列に
     `return ["1人目@example.com", "2人目@example.com"];` のように追記してください
5. 左メニュー「プロジェクトの設定」(歯車アイコン) →「全般」→「マイアプリ」→ ウェブアプリを追加 (`</>` アイコン)
6. 表示された `firebaseConfig` の値をコピー

### 2. 設定ファイルを作成

`js/firebase-config.js` はこのリポジトリに含まれています(GitHub Pages で公開するために
意図的にコミットしています)。このリポジトリをフォークして自分の Firebase プロジェクトで
使う場合は、そのファイルを開いて `apiKey` などの値を手順1でコピーした自分の値に
書き換えてください。

```bash
# 自分の設定でまっさらから作り直したい場合
cp js/firebase-config.example.js js/firebase-config.js
```

Firebase の Web 設定値(APIキーを含む)はブラウザに配信される公開前提の値なので、
コミットしても問題ありません。アクセス制御は APIキーではなく `firestore.rules` と
Firebase Authentication で行っています。
本当の機密情報(パスワードやサービスアカウントの鍵など)はこのファイルに書かないでください。

なお `js/firebase-config.js` が存在しない状態でアプリを開くと、
「セットアップが必要です」という案内画面が表示されます。

### 3. ローカルで起動

ブラウザの ES Modules 制限により、`index.html` を直接ダブルクリックして開く(`file://`)のでは動作しません。
簡易 HTTP サーバー経由で開いてください。

```bash
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

初回はログイン画面で「新規登録」タブからメールアドレスとパスワードを登録してください。

## スマホと PC でデータを共有する

同じ Firebase アカウント(同じメールアドレス)でログインすれば、スマホと PC で自動的にデータが同期されます。
ローカルの `python3 -m http.server` はそのマシン上でしかアクセスできないため、実際にスマホからも使うには、
以下のいずれかの方法でアプリをインターネット上に公開する必要があります。

### 公開方法 (GitHub Pages の例)

1. `js/firebase-config.js` (使う場合は `js/google-config.js` も) がコミットされていることを確認する
2. このブランチを `main` にマージ (または Pages の対象ブランチに指定)
3. リポジトリの Settings → Pages → Source で対象ブランチ・ルートディレクトリを選択
4. 発行された `https://<ユーザー名>.github.io/My-Expense-app/` にスマホ・PC両方からアクセス
5. Firebase コンソールの「Authentication」→「Settings」→「承認済みドメイン」に、その GitHub Pages のドメインを追加

Netlify や Vercel など、他の静的ホスティングサービスでも同様に公開できます。

## スプレッドシートからの移行 (CSV インポート)

今使っているスプレッドシートを以下の列構成の CSV にして保存し、「CSVインポート」ボタンから取り込めます:

| 日付 | 種別 | カテゴリ | 金額 | メモ |
|------|------|----------|------|------|
| 2026-07-20 | 支出 | 食費 | 1500 | スーパー |
| 2026/7/25 | 収入 | 給与 | 300000 | |

- **日付**: `2026-07-20` / `2026/7/20` / `2026年7月20日` / `26/7/20` (2桁年) のいずれの形式でも可
- **種別**: 「収入」「支出」「貯蓄」(`income` / `expense` / `save` / `投資` / `invest` も可)
- **金額**: 数値(カンマ・¥ 記号入りでも可)
- 1行目がヘッダー行の場合は自動的にスキップされます
- 形式を認識できない行はスキップされ、件数が表示されます
- 既存の記録と「日付・種別・カテゴリ・金額・メモ」が完全に一致する行は重複とみなして
  自動的にスキップされます(同じCSVを誤って2回読み込んでも二重登録されません。
  同じ内容の記録が本当に複数回ある場合は、件数分だけ正しく取り込まれます)

「概要」テンプレート系スプレッドシートの [取引] タブ(支出の表: 日付/金額/説明/カテゴリ、
収入の表: 同じ並びで右側に配置)をそのままCSVエクスポートした形式も自動判定して取り込めます。
カテゴリ名がアプリのカテゴリと完全一致しない場合(例: 「交通費」→「交通」、「水道光熱費」→「水道・光熱」)
は自動的に読み替え、対応表にないカテゴリは「その他支出」「その他収入」として取り込まれます。

### クレジットカードの利用履歴CSV

Vpassなど、カード会社サイトからダウンロードした利用履歴CSV(1行目が
「氏名,カード番号(マスク済み),カードブランド」、以降の行が「利用日,利用先,
利用金額,支払回数,今回回数,今回支払金額,備考」の形式)もそのまま取り込めます。
このCSVは Shift_JIS で保存されていることが多いため、文字化けする場合は自動的に
Shift_JIS として読み直します。プラス金額の行は「支出」として取り込まれ、カテゴリは利用先の
店名から自動推測されます(Suica/PASMOなどの交通系、コンビニ・飲食店などの食費系、
Google Play・Steam・Amazonなどの趣味・娯楽系を判定。判定できないものは「その他支出」)。
マイナス金額の行(返金・キャンセル)は「収入」・カテゴリ「カード返金」として
取り込まれ、対になる支出と相殺されます(このカテゴリは収入目標や Need/Want/Save の
収入には数えません)。

この形式のCSVは**確定明細**として扱われ、メールから取り込んだ未確定(仮)の記録と
自動で突き合わせます。詳しくは
[未確定(仮)と確定](#未確定仮と確定--メールとカード明細の二重登録を防ぐしくみ) を参照してください。

末尾の合計行(日付のない行)は取り込み対象から除外されますが、そこに記載された
合計金額と実際に読み取れた金額の合計を突き合わせ、一致しない場合はインポート前の
確認ダイアログに警告を表示します(一部の行が正しく取り込めていない可能性がある
ことを示します)。ただし**分割払いの行が含まれる場合は警告を出しません** —
CSVの合計行は「今回支払金額」の合計、取り込む金額は「利用金額」なので、
正しいファイルでも一致しないためです。この場合は代わりに、それぞれが何の金額かを
添えて両方の合計を表示します。

## 未確定(仮)と確定 — メールとカード明細の二重登録を防ぐしくみ

カードの「ご利用のお知らせ」メールは**速報**で、まだ売上が確定していません。
そのため確定時に金額や計上日が動くことがあり(海外利用の為替確定、
ガソリンスタンドなど)、キャンセルされれば請求に載りません。

そこで各記録に**どこから来たか (`source`)** を持たせています。

| source | 意味 | 一覧での見え方 |
| --- | --- | --- |
| `gmail` | 利用通知メールから取り込んだ。**未確定** | 「仮」バッジが付く |
| `card` | カード利用履歴CSVから取り込んだ。**確定版** | 印なし |
| `manual` | 手入力(現金・その他の支払い) | 印なし |

未確定の記録が期間内にあると、記録一覧の上に件数と合計が出ます。
「今どこまで確定しているか」が分かるので、収支がまだ動くかどうか判断できます。

### 確定明細を取り込んだとき

カード利用履歴CSVを取り込むと、**そのCSVの利用日の範囲**にあるカード由来の記録と
自動で突き合わせます(手入力の現金・その他は `source` が違うので対象外です)。
判定は確実なものから順に、店名の表記ゆれ(半角カナ・全角英数・空白)を
吸収したうえで行います:

1. 店名・日付・金額が一致
2. 日付と金額が一致 — メールとCSVで店名の書き方が大きく違う場合
3. 店名と金額が一致し、日付が3日以内 — 計上日がずれた場合 ※未確定の記録にのみ適用
4. 店名と日付が一致し、金額だけ違う — 為替確定などで金額が動いた場合 ※未確定の記録にのみ適用

結果は取り込み前の確認ダイアログにまとめて出ます:

- **一致した仮の記録** → 確定版の**日付と金額**で更新します。カテゴリとメモは
  上書きしません(手で直しているかもしれませんし、店名はメール側の方が読みやすいためです)
- **CSVにしかない行** → 新しく追加します
- **確定済みの記録と一致した行** → 「既に登録済み」としてスキップします
  (同じCSVを二度読み込んでも増えません)
- **確定明細に出てこなかった仮の記録** → **消さずに残し、警告を出します**。
  キャンセル済みか次回の請求に回った可能性がありますが、こちらでは区別できません。
  取り込み済みメールは再取得されないため、自動で消すと二度と戻せなくなります

なお、3・4 の緩い判定を確定済みの記録に使わないのは、同じ店の別の買い物を
同一視してしまうためです。

## 帳簿 (簿記の見方)

入力は今までどおり単式 (1件 = 日付・種別・カテゴリ・金額) のまま、複式の見方を
既存の記録から導出して表示します。**入力の手間はほぼ増えません**
(貸借対照表を出す場合だけ、期首残高の設定が1回と、記録ごとに現金か口座かの選択が
加わります)。

### 損益計算書

収益 − 費用 = 当期純利益。この当期純利益は、上の「収支」カードと**必ず同じ金額**に
なります (見方を変えただけで、別の数字にはなりません)。

- **貯蓄・投資は費用に入りません** — 現金が投資資産に形を変えただけで、
  簿記では資産の振替だからです
- **給与は総支給を収益に立てます** — 控除された社会保険料は「法定福利費」、
  所得税・住民税は「租税公課」として費用に振り分けます。手取りベースだと
  「年間いくら保険料と税金を払ったか」が帳簿のどこにも残らないためです。
  なお総支給ベースにしても収益と費用が同じだけ増えるので、当期純利益は変わりません

### 合計試算表

勘定科目ごとの借方合計・貸方合計です。**全体の借方合計と貸方合計は必ず一致します**
(貸借平均の原理)。一致していることを画面に出しているので、確かめられます。
残高ではなく、その期間に動いた金額の合計です。

### 貸借対照表

**期首日とその日の残高を1回だけ入れる**と、そのあとは記録から自動で計算されます
(「口座を設定」ボタン)。残高 = 期首残高 + 期首日から表示中の期間末までの増減、
という形です。

```
資産の部                  負債の部
  現金        ¥42,000       未払金      ¥900
  銀行口座 ¥1,014,309       ────────────
  投資信託   ¥320,000       負債合計    ¥900
  ─────────────
  資産合計 ¥1,376,309     純資産の部
                            純資産  ¥1,375,409
```

**期首純資産 + 当期純利益 = 期末純資産** になります。上の例だと
期首純資産 1,120,000 + 当期純利益 255,409 = 1,375,409 です
(貸借対照表と損益計算書がつながっていることの確認になります)。

**実際の残高と合わない場合は、記録していない支出・収入があります。**
銀行アプリの残高と突き合わせると記録漏れが見つかります。

#### 現金と銀行口座の区別

記録に「支払い・入金の口座」(現金 / 銀行口座) を持たせています。初期値は
支出が現金、収入と貯蓄が銀行口座です。カード払いはメール・カードCSVからの
取り込みで自動判別するので、選ぶ必要はありません。

この区別を入れる前の記録には値が無いので、同じ規則 (支出は現金、収入・貯蓄は
口座) で推定します。給与から天引きされる家賃だけは、現金を通らないので
銀行口座として扱います。

#### カードの未払金と引き落とし

カード利用は現金がすぐ出ていかないので、**支払日が来るまで「未払金」(負債)
として残ります**。締め日・支払日を設定しておくと、各利用の引き落とし日を計算し、
その日に銀行口座から落ちたものとして自動で仕訳を立てます (記録一覧には出ません)。

```
(借) 未払金 30,000  (貸) 銀行口座 30,000     ← 2/26 カードの引き落とし
```

期首時点で残っていたカードの請求 (期首残高に入れた未払金) は、期首日以降で
最初に来る支払日にまとめて引き落とされたものとして扱います。

なお立替金は今のところ費用として集計しているため、貸借対照表には資産として
出てきません。

### 仕訳帳

記録1件ずつを借方 / 貸方の形にしたものです。

- **カード払いは貸方が「未払金」(負債)** になります。現金はまだ出ていかないためです
- **給与は複合仕訳**になります:

```
(借) 現金預金    294,309    (貸) 給与  362,309
(借) 法定福利費   48,000
(借) 租税公課     20,000
```

寮社宅費は「受け取って払った」形にしているため控除に立てず、別の「住居」の支出
として記録されています (二重計上を避けるため)。

簿記の教科書どおりの扱いとこのアプリの集計が違うところ (立替金・立替金返金・
カード返金) には、仕訳帳の各行に違いを説明する注記を出しています。

### 貸借がずれたとき

給与明細の内訳が支給合計と噛み合っていない場合だけ、貸借がずれます。その場合は
黙って捨てずに「差額 (要確認)」という科目を立てて表に出すので、**入力の間違いに
気づけます**。

## AI に分析してもらう (分析用エクスポート)

記録一覧の「分析用に書き出す」ボタンで JSON を1つ書き出し、それを Claude などに
添付すると、家計の相談ができます。

CSV エクスポートは5列(日付/種別/カテゴリ/金額/メモ)しかないため、予算・収入目標・
立替の紐づけ・給与明細の内訳が落ちます。分析用エクスポートはそれらを含みます。

含まれるもの:

- `entries` … 全記録 (立替フラグ、返金や家賃の紐づけ、給与明細の内訳、登録日つき)
- `budgets` / `incomeBudgets` … 予算と収入目標 (賞与の設定を含む)
- `categories` / `needWantSave` … カテゴリ定義と 50:30:20 の分類
- `howToRead` … このアプリ独自の集計ルールの説明

`howToRead` を入れているのは、**貯蓄を支出に数えない・返金を収入に数えない・
年間の目標は経過月数で按分する**といったルールを知らずに素の記録から集計すると、
アプリの画面と違う数字が出てしまうためです。

聞き方の例:

- 「今月、予算に対してどうだった?」
- 「去年の同じ月と比べて何が増えた?」
- 「Need/Want/Save の比率を目安に近づけるなら、どこを削るのが現実的?」

なお、このファイルには収入も含めた家計の全記録が入ります。渡す相手は選んでください。

## 立替金(仮払い)について

出張費・接待費など、**自分が先に払って後で会社から返金される支出**を管理する機能です。

### 使い方

1. 種別「支出」で記録するとき、「立替払い(あとで会社などから返金される)」にチェックを入れる
2. 「立替金(未回収)」セクションに未回収合計と一覧が表示される
3. 返金されたら、その行の「精算」ボタンを押して返金日を入力する
4. 同額の収入(カテゴリ「立替金返金」)が自動で記録され、未回収リストから消える

未回収の一覧は**表示中の月に関係なく常に全期間が対象**です(先月立て替えた分も、返金されるまで表示され続けます)。

### 集計での扱い

実際のお金の動きに忠実に、**支払った時点では通常の支出として計上**し、**返金時に収入として計上して相殺**します。そのため:

- 立て替えた月は、支出・収支・累計貯金額がその分だけ一時的にマイナスに振れます
- 返金された月に収入として戻り、収支が相殺されます
- **Need / Want / Save グラフは立て替えた月だけ歪みます**(立替の支出がWant/Needを押し上げるため)。返金のほうは「稼いだお金」ではないので収入には数えず、目標額が水増しされないようにしています
- 同じ理由で、収入の「予定と実績」の実績にも返金は含まれません(サマリーの「収入」カードには相殺のため含まれます)

### 補足

- 精算済みかどうかは「返金記録が存在するか」で判定しています。そのため**返金の記録を削除すると、その立替は自動的に未回収に戻ります**
- 精算後に立替の金額を変更しても、作成済みの返金記録の金額は追従しません。差額が出た場合は返金記録を手動で修正してください
- CSVエクスポートは従来どおり5列(日付/種別/カテゴリ/金額/メモ)で、立替フラグは含まれません(金額の集計は正しいまま、立替情報だけが落ちます)

## 給与明細・賞与明細の内訳について

会社からの給与・賞与は、額面(支給合計)と実際に振り込まれる金額(手取り)が
社会保険料・税金などの天引きにより異なります。一般的な給与明細・賞与明細の
フォーマットに合わせて、以下の内訳を記録できます:

1. 種別「収入」・カテゴリ「給与」または「賞与」を選ぶ
2. 「給与明細(または賞与明細)の内訳を入力する」ボタンを押す
3. カテゴリに応じて入力項目が切り替わります:
   - **給与**: 支給(本給・勤務地手当・通勤手当・時間外勤務手当・給与調整) /
     控除(寮社宅費・健康保険・介護保険・厚生年金・雇用保険料・所得税・住民税・
     その他控除(慶弔掛金・福祉会費・組合費・共済など、会社独自の小額の控除項目を
     まとめて入力))
     - 「給与調整」は遡及差額などでマイナスになることがあるため、負の数も入力できます
   - **賞与**: 支給(賞与額) / 控除(健康保険・介護保険・子ども支援金・厚生年金・
     雇用保険料・所得税) — 賞与では住民税は天引きされないため項目がありません
4. 入力すると、手取り額(支給合計 − 控除合計)が自動計算され、
   上の「金額」欄に反映されます

家計簿は実際にお金が動いた額を記録するものなので、控除される社会保険料・税金は
そもそも手元に届かないお金として扱い、**収入・収支・累計貯金額には手取り額のみ**が
影響します。入力した内訳は記録一覧の「内訳」ボタンからポップアップで見返せます

### 家賃が給与から天引きされている場合 (寮社宅費)

家賃は税金や社会保険料とは性質が違います。税金は**そもそも手元に入らないお金**ですが、
家賃は**生活に使ったお金**です。同じように控除へ入れて手取りだけを収入にすると、
住居カテゴリの実績がゼロになり、予算も組めず、Need/Want/Save の比率も歪み、
天引きになる前の月と数字が地続きでなくなります。

そこで「寮社宅費」だけは特別扱いし、**受け取って、家賃として払った**形で記録します。

1. 給与明細の控除欄「寮社宅費 (家賃の天引き)」に金額を入れる
2. 差引支給額(振込額)は給与明細どおりに計算される
3. 同額の「支出・住居」が**自動で記録される**
4. 収入として記録される金額は「振込額 + 寮社宅費」になる

例: 支給合計 362,309 / 控除合計 77,765 (うち寮社宅費 16,935) の場合

| | 金額 |
|---|---|
| 差引支給額(振込額) | ¥284,544 |
| 収入として記録 | ¥301,479 |
| 支出・住居として記録 | ¥16,935 |
| 収支 | ¥284,544 (実際に増えたお金と一致) |

収入の金額が振込額と違うのは、家賃を両側に立てているためです。入力欄の下と
内訳ポップアップの両方に、この内訳が表示されます。

自動で作られる住居の支出は、**給与の記録と対**になっています(立替金と返金の関係と同じ)。
給与の金額を直せば追従し、寮社宅費を0にすれば消え、給与の記録を削除すれば
一緒に削除されます。家賃の支出だけが取り残されて累計貯金額がずれることはありません。
(右上の×ボタン・背景クリック・Escapeキーのいずれでも閉じられます)。

## Need / Want / Save (50:30:20) について

家計の定番ルール「50:30:20」に基づき、今月の収入を基準として以下のように分類します:

- **Need (必要, 目標50%)**: 食費・住居・水道光熱・通信・交通・医療・教育・日用品
- **Want (欲しい物, 目標30%)**: 交際費・趣味娯楽・衣服美容・その他支出
- **Save (貯蓄, 目標20%)**: 収入 − Need − Want (実際に手元に残った金額)

上記に無い支出カテゴリは自動的にWant扱いになります。カテゴリ分類を変更したい場合は
`js/app.js` の `NEED_CATEGORIES` / `WANT_CATEGORIES` を編集してください。

「今月の予算」の各カテゴリ名の左には、Need(青)/Want(黄)を示す
色ドットが付き、グラフの凡例にも該当カテゴリの一覧が表示されるため、どのカテゴリが
どちらに分類されているか一目で分かります。

## メールからの読み込み機能のセットアップ

「メールから読み込み」ボタンは、Gmail内の Vpass (三井住友カード) の「ご利用のお知らせ」メールを検索し、
利用明細を自動で記録として取り込みます。お店の名前から Suica/PASMO 等の交通系は「交通」、
コンビニ・飲食店は「食費」など、よくあるパターンをある程度自動でカテゴリ分けしますが、
判定できないものは「その他支出」になるため、あとで見直してください。一度取り込んだメールは記録され、
重複して取り込まれることはありません。

使うには、Google Cloud 側でOAuth認証の設定が別途必要です(Firebaseと同じGoogle Cloudプロジェクトを流用できます)。

1. [Google Cloud Console](https://console.cloud.google.com/) で、Firebaseプロジェクトと同じプロジェクトを選択
2. 「APIとサービス」→「ライブラリ」で **Gmail API** を検索して有効化
3. 「APIとサービス」→「OAuth同意画面」を設定
   - User Type は「External」を選択
   - スコープに `https://www.googleapis.com/auth/gmail.readonly` を追加
   - 「テストユーザー」に自分のGmailアドレスを追加(この状態なら審査不要ですぐ使えます)
4. 「認証情報」→「認証情報を作成」→「OAuthクライアントID」
   - アプリケーションの種類: 「ウェブアプリケーション」
   - 「承認済みのJavaScript生成元」に、公開先のURL (`https://<ユーザー名>.github.io` など) と、
     ローカルで試す場合は `http://localhost:8000` を追加
5. 作成されたクライアントIDをコピー

```bash
cp js/google-config.example.js js/google-config.js
```

`js/google-config.js` を開き、`YOUR_CLIENT_ID...` の部分をコピーしたクライアントIDに置き換えます。
`js/google-config.js` も `firebase-config.js` と同じくコミット済みです
(OAuthクライアントIDも公開前提の値です)。利用できるオリジンは Google Cloud 側の
「承認済みの JavaScript 生成元」で制限してください。

> **CSVエクスポートの往復について**
> エクスポートするCSVは「日付・種別・カテゴリ・金額・メモ」の5列だけなので、
> 取り込み元(`source`)は書き出されません。エクスポートしたCSVを読み直すと、
> その記録は「手入力」と同じ扱い(印なし)になります。取り込み元まで含めて
> 書き出したい場合は「分析用に書き出す」(JSON)を使ってください。

## データの保存について

記録は Firestore に保存され、ブラウザにはオフラインキャッシュ(IndexedDB)が作られます。
オフラインでも記録の閲覧・追加は可能で、オンラインに戻ると自動的に同期されます。

## 構成

```
index.html                       … 画面 (UI)
css/style.css                    … スタイル
js/app.js                        … ロジック (認証・Firestore同期・集計・CSV入出力)
js/firebase-config.example.js    … Firebase設定のテンプレート
js/firebase-config.js            … Firebase設定 (公開前提の値、コミット済み)
js/google-config.example.js      … Google OAuth設定のテンプレート (メール読み込み用)
js/google-config.js              … Google OAuth設定 (公開前提の値、コミット済み)
firestore.rules                  … Firestoreセキュリティルール
test/                            … ブラウザを動かす自動テスト (実行方法は test/README.md)
```

フレームワークやビルドツールは使用していません (Vanilla JS)。
